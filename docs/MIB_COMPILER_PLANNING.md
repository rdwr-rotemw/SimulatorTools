## 1. Feature Overview

### What This Feature Does

Takes two inputs from the user:

1. **MIB ZIP file** — A ZIP archive containing `.mib` files for a specific DefensePro version (downloaded from the Radware portal)
2. **OIDs PDF file** — The DefensePro OID Document PDF for the same version (also from the Radware portal)

And produces two output files:

1. **`.cmf` file** (Compiled MIB File) — Contains every OID with its numeric identifier, label name, data type, access level, index type, ranges, and enum definitions. Generated **from the MIB files** because they contain the authoritative machine-readable data (exact ranges, enum values, textual conventions).

2. **`.var` file** (Variable Information File) — Contains:
   - Scalar variable definitions with default value types
   - Static table row definitions
   - **Dynamic row creation blocks** (`%drow`/`%dcol`/`%setaction`) — Generated by **cross-referencing MIB data with the OIDs PDF**, because the PDF provides the table-to-column mapping, index information, and description text needed to determine dynamic row creation type and delete-action columns.

### Why Both Sources Are Needed

| Data Point | MIB Files | OIDs PDF |
|---|---|---|
| OID numeric path | ✅ | ✅ |
| Label name | ✅ | ✅ |
| Data type + Syntax | ✅ (authoritative) | ✅ (simplified) |
| Min/max ranges | ✅ | ❌ |
| Enum values | ✅ | ❌ (only in description text) |
| Access level | ✅ | ✅ |
| Table name | ✅ (via SEQUENCE) | ✅ (explicit column) |
| Index columns | ✅ (via INDEX clause) | ✅ (explicit column) |
| Column-to-table mapping | ✅ (implicit) | ✅ (explicit, easier to parse) |
| Description text with deletion hints | ❌ (not in compiled output) | ✅ |
| RowStatus column identification | ✅ | ✅ |

The MIB files are the authoritative source for `.cmf` generation. The OIDs PDF is the critical enabler for dynamic row creation because it provides clear table structure and description text that contains deletion-action hints for `newinstance` type tables.

## 3. Data Models (`models.py`)

Define all Pydantic models used throughout the module.

```python
from pydantic import BaseModel
from typing import Optional
from enum import Enum


class AccessLevel(str, Enum):
    RO = "RO"
    RW = "RW"
    WO = "WO"
    NA = "NA"
    CREATE = "Create"  # Seen in OIDs PDF for RowStatus tables


class DynamicRowType(str, Enum):
    ROWSTATUS = "rowstatus"
    RMONSTATUS = "rmonstatus"
    NEWINSTANCE = "newinstance"


class OidEntry(BaseModel):
    """A single OID as parsed from MIB files."""
    oid: str                          # e.g., "1.3.6.1.2.1.1.1"
    label: str                        # e.g., "sysDescr"
    syntax: str                       # e.g., "OctetString", "INTEGER", "Counter"
    access: AccessLevel
    is_table_entry: bool = False      # True if this is a TABLE ENTRY object
    is_table_column: bool = False
    table_name: Optional[str] = None  # e.g., "ifTable"
    entry_name: Optional[str] = None  # e.g., "ifEntry"
    index_columns: list[str] = []     # e.g., ["ifIndex"] — only set on entry objects
    min_range: Optional[int] = None
    max_range: Optional[int] = None
    has_enum: bool = False
    enum_values: dict[str, int] = {}  # e.g., {"up": 1, "down": 2, "testing": 3}
    description: str = ""
    mib_module: str = ""              # e.g., "IF-MIB"
    display_hint: Optional[str] = None
    # CMF-specific fields computed during generation
    index_type: str = "S"             # "S" for scalar, "C1"/"C2"/etc for table columns
    range_str: str = ""               # e.g., "(0,255)"
    enum_flag: str = "d"              # "d" for default, "e" for enum


class PdfTableInfo(BaseModel):
    """Table structure info extracted from the OIDs PDF."""
    table_name: str                   # e.g., "rdwrSyslogServerTable"
    entry_name: str                   # e.g., "rdwrSyslogServerEntry" (derived)
    columns: list["PdfColumnInfo"]
    index_columns: list[str]          # Column labels that serve as index


class PdfColumnInfo(BaseModel):
    """A single column within a table, as extracted from the OIDs PDF."""
    oid: str
    label: str
    syntax: str
    table_name: str
    index_name: str                   # The index column(s) for this table
    access: str                       # "RO", "RW", "Create"
    description: str


class DynamicRowConfig(BaseModel):
    """Configuration for a single dynamic row creation block."""
    entry_name: str                   # e.g., "rdwrSyslogServerEntry"
    row_type: DynamicRowType          # rowstatus, rmonstatus, or newinstance
    columns: list["DynamicColumnConfig"]
    # For newinstance only:
    setaction_column: Optional[str] = None   # Column label for %setaction
    setaction_type: Optional[str] = None     # Data type of the setaction column
    setaction_value: Optional[str] = None    # Value that triggers row deletion
    # Metadata
    is_fully_detected: bool = True    # False if we couldn't determine delete value
    detection_warning: Optional[str] = None  # Reason for comment-out


class DynamicColumnConfig(BaseModel):
    """A single %dcol line's configuration."""
    label: str
    required: str                     # "Req" or "NotReq"
    syntax: str
    access: str                       # "RO" or "RW"
    value_info: str                   # e.g., "lastset(1)", "rowstatus(1)", "dfixed(0)"


class CompilationResult(BaseModel):
    """Result returned to the frontend after compilation."""
    success: bool
    cmf_path: Optional[str] = None
    var_path: Optional[str] = None
    version: str = ""
    stats: dict = {}                  # OID count, table count, dynamic row count, etc.

    errors: list[str] = []            # Fatal issues (if success=False)
```

## 4. MIB Parser (`mib_parser.py`)

### Purpose

Parse `.mib` files from a user-uploaded ZIP archive and extract all OID definitions with full metadata (types, ranges, enums, indexes, access levels, descriptions).

### Implementation Approach

Use `pysmi` to compile MIB files. `pysmi` handles:
- MIB interdependency resolution (IMPORTS)
- SEQUENCE/TABLE/ENTRY relationships
- Textual convention resolution (e.g., `DisplayString` → `OctetString(0..255)`)
- Range constraints
- Enum value extraction
- INDEX clause parsing

### Key Implementation Details

```python
class MibParser:
    """Parse MIB files from a ZIP archive using pysmi."""

    def __init__(self, zip_path: str, work_dir: str):
        """
        Args:
            zip_path: Path to the uploaded MIB ZIP file
            work_dir: Temporary directory to extract MIB files into
        """

    def parse(self) -> list[OidEntry]:
        """
        Extract ZIP, parse all .mib files, return list of OidEntry.

        Steps:
        1. Extract ZIP to work_dir
        2. Use pysmi MibParser + MibCompiler to parse all .mib files
        3. Walk the compiled MIB tree and extract OidEntry for each node
        4. Resolve table/column relationships
        5. Sort entries in lexicographic OID order
        6. Return list of OidEntry

        The parser should handle:
        - Multiple MIB files with interdependencies
        - Standard MIBs (RFC1213, IF-MIB, etc.) — pysmi has built-in knowledge
        - Radware proprietary MIBs
        - Textual conventions (RowStatus, DisplayString, etc.)
        - SEQUENCE definitions to identify table structures
        - INDEX clauses to identify index columns
        - SIZE constraints for ranges
        - DEFVAL for default values
        """

    def _extract_zip(self) -> list[str]:
        """Extract ZIP and return list of .mib file paths."""

    def _determine_table_relationships(self, entries: list[OidEntry]) -> list[OidEntry]:
        """
        Post-process entries to set table_name, entry_name, index_columns,
        and index_type (S for scalar, C1/C2/... for table columns).

        The INDEX clause on the Entry object tells us which columns are indexes.
        Column numbering (C1, C2, ...) is based on lexicographic OID order within the table.
        """

    def _extract_enum_values(self, mib_node) -> dict[str, int]:
        """Extract enum name→value mapping from a MIB node's named values."""

    def _extract_range(self, mib_node) -> tuple[Optional[int], Optional[int]]:
        """Extract min/max range from SIZE or range constraints."""

    def get_mib_modules(self) -> list[tuple[str, str]]:
        """
        Return list of (filename, module_name) tuples.
        e.g., [("radwaremib.mib", "RADWARE-MIB"), ("dosmib.mib", "DOS-MIB")]
        Used for .mif file generation.
        """
```

### pysmi Usage Notes

- `pysmi` compiles MIBs into an internal representation. Use `pysmi.reader.FileReader` to read from the extracted directory.
- Standard MIBs (SNMPv2-SMI, SNMPv2-TC, SNMPv2-CONF, etc.) are built into pysmi and don't need to be in the ZIP.
- If pysmi's built-in MIB compilation is too complex to control, an alternative approach is to use `pysmi` only for parsing and then walk the parsed AST manually. The key classes are in `pysmi.parser.smi` and `pysnmp.smi.builder`.
- **Fallback approach**: If `pysmi` proves problematic, a simpler (but more work) approach is to write a custom parser using regex for the specific MIB constructs we need. The MIB files follow SMIv2 syntax which is relatively structured. This fallback should only be used if pysmi integration becomes a blocker.

## 5. PDF Parser (`pdf_parser.py`)

### Purpose

Parse the DefensePro OIDs PDF to extract table structure information that will be used for dynamic row creation detection.

### What We Extract

From each table in the PDF:
- **Table Name** — e.g., `rdwrSyslogServerTable`
- **Columns** — All OIDs that belong to that table, with:
  - OID number
  - Label name
  - Syntax (data type)
  - Index column name(s)
  - Access level (RO, RW, Create)
  - Description text (critical for newinstance detection)

### PDF Structure

The OIDs PDF contains structured tables with these columns:

```
| OID | Label | Syntax | Table Name | Index | Access | Description |
```

- Scalar OIDs have `Table Name = "NO TABLE"` or `"NOT TABLE"`
- Table column OIDs have the actual table name in the `Table Name` column
- The `Index` column shows which column(s) serve as the table index
- The `Access` column can be `RO`, `RW`, or `Create`
- The PDF is organized by MIB module with section headers like `RADWARE-MIB`, `IDS-MIB`, etc.

### Implementation

```python
class PdfParser:
    """Parse DefensePro OIDs PDF to extract table structure information."""

    def __init__(self, pdf_path: str):
        self.pdf_path = pdf_path

    def parse(self) -> list[PdfTableInfo]:
        """
        Parse the entire PDF and return table structure information.

        Steps:
        1. Use pdfplumber to open the PDF
        2. Iterate through all pages
        3. Extract tables from each page
        4. Filter out scalar entries (Table Name = "NO TABLE")
        5. Group columns by table name
        6. Identify index columns for each table
        7. Return list of PdfTableInfo

        Important parsing considerations:
        - Multi-line cells: Labels and descriptions can wrap across lines
        - Page breaks: A table can span multiple pages
        - Column alignment: Use pdfplumber's table extraction with layout mode
        - Section headers: Lines like "RADWARE-MIB" appear between tables
        - The PDF uses layout-based tables, not HTML-style tables

        If pdfplumber's table extraction doesn't work well with this PDF layout,
        fall back to text extraction with layout mode (pdftotext -layout equivalent)
        and parse using column position offsets.
        """

    def _extract_version(self) -> str:
        """
        Extract DefensePro version from PDF title/header.
        e.g., "DefensePro X version 10.12.0.0 OID Document" → "10_12"
        """

    def _parse_table_row(self, row: list) -> Optional[PdfColumnInfo]:
        """Parse a single row from a PDF table into a PdfColumnInfo."""

    def _group_by_table(self, columns: list[PdfColumnInfo]) -> list[PdfTableInfo]:
        """
        Group column entries by their table_name field.
        Identify the index column(s) for each table.
        Derive the entry_name from the table_name (e.g., "fooTable" → "fooEntry").
        """
```

### Fallback Parsing Strategy

If pdfplumber's table extraction fails (the OIDs PDF uses a complex layout), use text-mode parsing:

```bash
pdftotext -layout oids.pdf -
```

This produces fixed-width column output that can be parsed by detecting column boundaries from the header row (`OID    Label    Syntax    Table Name    Index    Access    Description`). Each column starts at a fixed character position.

The parser should:
1. Detect header rows by looking for the pattern `OID.*Label.*Syntax.*Table Name.*Index.*Access.*Description`
2. Record the character position of each column header
3. Parse subsequent lines by splitting at those positions
4. Handle continuation lines (lines that start with whitespace and continue a previous entry's data)

## 6. Dynamic Row Detector (`dynamic_row_detector.py`)

### Purpose

Analyze table structures (from both MIB and PDF data) and determine which tables support dynamic row creation, what type of creation mechanism they use, and for `newinstance` tables, which column and value control row deletion.

### Detection Logic

#### Type 1: `rowstatus`

**Detection**: Any table that has a column with `Syntax = RowStatus`.

RowStatus is an SNMPv2 textual convention (RFC 2580). The column controls row lifecycle with values: `active(1)`, `notInService(2)`, `notReady(3)`, `createAndGo(4)`, `createAndWait(5)`, `destroy(6)`.

SAPRO handles RowStatus semantics internally — we just need to identify the column and declare it.

**Detection sources**:
- MIB: Column syntax resolves to `RowStatus` textual convention
- PDF: Column syntax is literally `"RowStatus"` or description mentions `createAndGo`/`createAndWait`

**Output**:
```
%drow <entryName> rowstatus
%dcol <rowStatusColumn> Req RowStatus RW rowstatus(1)
%dcol <otherRWColumn> Req <type> RW lastset(<default>)
%dcol <otherROColumn> NotReq <type> RO fixed(<default>)
%dcol <indexColumn> NotReq <type> RW dfixed(0)
```

#### Type 2: `rmonstatus`

**Detection**: Any table that has a column with `Syntax = EntryStatus` (RFC 1757 RMON EntryStatus textual convention).

EntryStatus values: `valid(1)`, `createRequest(2)`, `underCreation(3)`, `invalid(4)`.

**Detection sources**:
- MIB: Column syntax resolves to `EntryStatus` textual convention
- PDF: Column syntax is literally `"EntryStatus"`

**Note**: In the current DefensePro OIDs PDF (v10.12), no columns use `EntryStatus` as their syntax. Some columns have "EntryStatus" in their *label name* (e.g., `rsIDSHwPoliciesTableEntryStatus`) but their actual syntax is `RowStatus`. The detector must check the **syntax**, not the label name.

**Output** (same structure as rowstatus but with rmonstatus type):
```
%drow <entryName> rmonstatus
%dcol <entryStatusColumn> Req EntryStatus RW rmonstatus(1)
...
```

#### Type 3: `newinstance`

**Detection**: A table that has RW columns but NO RowStatus or EntryStatus column, AND has description text indicating that setting a column to a specific value causes row deletion/invalidation.

This is the most complex detection. The detector must scan description text for patterns that indicate row deletion behavior.

### Newinstance Description Patterns

Based on analysis of the DefensePro OIDs PDF v10.12, these are the three confirmed patterns:

#### Pattern A: Explicit "Setting to value invalid(N) invalidates"

**Regex**: `[Ss]etting\s+this\s+object\s+to\s+(?:the\s+)?value\s+(\w+)\((\d+)\)\s+has\s+the\s+effect\s+of\s+invalidat`

**What it captures**:
- Group 1: The value name (e.g., "invalid")
- Group 2: The numeric value (e.g., "2")

**Found in**:
- `ip6NetToMediaTable` → column `ip6NetToMediaType`, delete value `2` (invalid)
- `ipRouteTable` → column `ipRouteType`, delete value `2` (invalid)

**Confidence**: HIGH — the description explicitly states the value and its effect.

#### Pattern B: "Status is invalid ... entry will be deleted"

**Regex**: `[Ss]tatus\s+is\s+invalid.*(?:entry|community)\s+.*(?:will\s+be\s+)?deleted`

**What it captures**: No value directly in the regex. Must infer the value:
- Look for `invalid` keyword → the delete value is the enum value for "invalid"
- Cross-reference with MIB enum definitions if available
- If no enum, default to `2` (standard "invalid" value in SNMP conventions)

**Found in**:
- `rndCommunityTable` → column `rndCommunityStatus`, delete value for "invalid" state

**Confidence**: MEDIUM-HIGH — the pattern is clear but the delete value needs inference.

#### Pattern C: "Validity ... Invalid indicates"

**Regex**: `[Vv]alidity.*[Ii]nvalid\s+indicates`

**What it captures**: Similar to Pattern B. The column name typically contains "Status" or "Valid".

**Found in**:
- `rsIpAddrTable` → column `rsIpAdEntStatus`, delete value for "invalid" state

**Confidence**: MEDIUM — less explicit than Pattern A, but combined with column name heuristics (contains "Status"), reliable enough.

### Handling Undetectable Cases

If a table has RW columns but:
- No RowStatus/EntryStatus column
- No description text matching any of the three patterns above

Then this table might support `newinstance` but we cannot determine the `%setaction` parameters. In this case:

**Generate the entire `%drow`/`%dcol` block as comments (prefixed with `#`)**

Add a human-readable comment explaining why:

```
# WARNING: Table rsIcmpRdEntry may support dynamic row creation (has RW columns)
# but the delete-action column and value could not be auto-detected.
# To enable, uncomment the block below and fill in the %setaction line.
#%drow rsIcmpRdEntry newinstance
#%dcol rsIcmpRdIpAddr NotReq IPADDR RO fixed(0.0.0.0)
#%dcol rsIcmpRdIpAdvAddr NotReq IPADDR RW lastset(0.0.0.0)
#...
#%setaction <column_name> <type> <value> deleterow()
```

This ensures the `.var` file always has valid syntax and nothing is lost.

### Implementation

```python
class DynamicRowDetector:
    """Detect dynamic row creation type and parameters for SNMP tables."""

    # Regex patterns for newinstance detection
    PATTERN_A = re.compile(
        r'[Ss]etting\s+this\s+object\s+to\s+(?:the\s+)?value\s+'
        r'(\w+)\((\d+)\)\s+has\s+the\s+effect\s+of\s+invalidat'
    )
    PATTERN_B = re.compile(
        r'[Ss]tatus\s+is\s+invalid.*(?:entry|community)\s+.*(?:will\s+be\s+)?deleted',
        re.DOTALL
    )
    PATTERN_C = re.compile(
        r'[Vv]alidity.*[Ii]nvalid\s+indicates'
    )

    def __init__(
        self,
        mib_entries: list[OidEntry],
        pdf_tables: list[PdfTableInfo]
    ):
        """
        Args:
            mib_entries: All OID entries parsed from MIB files
            pdf_tables: Table structure info parsed from OIDs PDF
        """

    def detect_all(self) -> list[DynamicRowConfig]:
        """
        Analyze all tables and return dynamic row configurations.

        Steps:
        1. Build a lookup of table_name → list of columns from both MIB and PDF
        2. For each table:
           a. Check if any column has RowStatus syntax → rowstatus type
           b. Check if any column has EntryStatus syntax → rmonstatus type
           c. If neither, check if table has RW columns → potential newinstance
              - Scan all column descriptions for Pattern A, B, or C
              - If found: create fully-detected newinstance config
              - If not found: create commented-out config with warning
        3. For each detected table, build the full DynamicRowConfig with all %dcol entries
        """

    def _detect_table_type(self, table: PdfTableInfo, mib_columns: list[OidEntry]) -> Optional[DynamicRowType]:
        """Determine the dynamic row creation type for a table."""

    def _detect_newinstance_delete_action(
        self,
        table: PdfTableInfo,
        mib_columns: list[OidEntry]
    ) -> tuple[Optional[str], Optional[str], Optional[str], bool, Optional[str]]:
        """
        For a potential newinstance table, try to find the delete-action column and value.

        Returns:
            (column_label, column_type, delete_value, is_detected, warning_message)
            If is_detected is False, the block should be commented out.
        """

    def _build_dcol_configs(
        self,
        table: PdfTableInfo,
        mib_columns: list[OidEntry],
        row_type: DynamicRowType
    ) -> list[DynamicColumnConfig]:
        """
        Build the list of %dcol configurations for a table.

        Rules (from SAPRO guide):
        - Index columns: required="NotReq"
        - RW non-index columns: required="Req"
        - RO columns: required="NotReq"

        Value info mapping:
        - RowStatus column: rowstatus(1)
        - EntryStatus column: rmonstatus(1)
        - Index columns: dfixed(0) or dfixed(0.0.0.0) for IpAddress
        - RW columns: lastset(<default>) or r_lastset(min, max, default) if range known
        - RO Counter: randomup(0, 100)
        - RO Gauge: random(1000, 100)
        - RO Integer: fixed(1)
        - RO OctetString: fixed(0x00)
        - RO TimeTicks: clock(0)
        - RO IpAddress: fixed(0.0.0.0)
        - RO ObjectID: fixed(0.0)
        """

    def _get_default_value_info(self, syntax: str, access: str, is_index: bool, row_type: DynamicRowType) -> str:
        """Return the appropriate value info string based on type, access, and role."""
```

## 7. CMF Generator (`cmf_generator.py`)

### Purpose

Generate a `.cmf` file from parsed MIB data. The CMF file is SAPRO's compiled MIB format.

### CMF File Format

Each line represents one OID entry (space-separated fields):

```
<oid> <label> <syntax> <access> <index_type> <range> <enum_flag>
```

Example lines from a real CMF:
```
1.3.6.1.2.1.1.1 sysDescr OctetString RO S (0,255) d
1.3.6.1.2.1.1.2 sysObjectID ObjectID RO S (0,0) d
1.3.6.1.2.1.2.2.1.1 ifIndex Integer RO C1 (0,2147483647) d
1.3.6.1.2.1.2.2.1.3 ifType Integer RO C3 (0,2147483647) e
```

**Field definitions**:

| Field | Description | Values |
|---|---|---|
| `oid` | Numeric OID without leading dot | `1.3.6.1.2.1.1.1` |
| `label` | SNMP label name | `sysDescr` |
| `syntax` | SNMP data type | `Integer`, `OctetString`, `Counter`, `Gauge`, `TimeTicks`, `IpAddress`, `ObjectID`, `Counter64`, `Bits` |
| `access` | Access level | `RO`, `RW`, `WO`, `NA` |
| `index_type` | `S` for scalar, `C<n>` for table column | `S`, `C1`, `C2`, ... |
| `range` | `(min,max)` value range | `(0,255)`, `(-2147483648,2147483647)` |
| `enum_flag` | `e` if has enum values, `d` otherwise | `d` or `e` |

After the OID entries, the CMF file also contains **enum value definitions**:

```
%ev <label> <value_name> <value_number>
```

Example:
```
%ev ifType other 1
%ev ifType regular1822 2
```

```python
class CmfGenerator:
    """Generate SAPRO .cmf files from parsed MIB data."""

    # Default ranges per SNMP type (used when MIB doesn't specify a range)
    DEFAULT_RANGES = {
        "Integer": "(-2147483648,2147483647)",
        "INTEGER": "(-2147483648,2147483647)",
        "Counter": "(0,4294967295)",
        "Counter64": "(0,18446744073709551615)",
        "Gauge": "(0,4294967295)",
        "TimeTicks": "(0,4294967295)",
        "OctetString": "(0,255)",
        "IpAddress": "(0,0)",
        "ObjectID": "(0,0)",
        "Bits": "(0,0)",
        "Opaque": "(0,0)",
    }

    def __init__(self, oid_entries: list[OidEntry]):
        self.entries = oid_entries

    def generate(self, output_path: str) -> str:
        """
        Generate the .cmf file.

        Steps:
        1. Sort entries by OID in lexicographic order
        2. Write each entry as a space-separated line
        3. After all entries, write enum definitions (%ev lines)
        4. Return the output file path

        Important:
        - OID should NOT have a leading dot
        - Entries must be sorted lexicographically by OID
        - Enum values (%ev) come at the end of the file, grouped by label
        """

    def _format_entry_line(self, entry: OidEntry) -> str:
        """Format a single OID entry line for the CMF file."""

    def _format_enum_lines(self, entry: OidEntry) -> list[str]:
        """Format %ev lines for an entry with enum values."""

    def _normalize_syntax(self, syntax: str) -> str:
        """
        Normalize MIB syntax to CMF syntax names.
        e.g., "INTEGER" → "Integer", "OCTET STRING" → "OctetString",
        "DisplayString" → "OctetString", "RowStatus" → "Integer",
        "Counter32" → "Counter", "Gauge32" → "Gauge",
        "IpAddress" → "IpAddress", "OBJECT IDENTIFIER" → "ObjectID"
        """

    def _compute_range(self, entry: OidEntry) -> str:
        """
        Compute the range string.
        Use MIB-defined range if available, otherwise use DEFAULT_RANGES.
        """
```

```python
class VarGenerator:
    """Generate SAPRO .var files with scalars, tables, and dynamic row creation."""

    DEFAULT_NUM_ROWS = 2  # Default number of static rows per table

    def __init__(
        self,
        oid_entries: list[OidEntry],
        dynamic_rows: list[DynamicRowConfig],
        version: str,
        num_rows: int = 2
    ):
        """
        Args:
            oid_entries: All OID entries from MIB parsing
            dynamic_rows: Dynamic row configurations from detection
            version: DefensePro version string
            num_rows: Default number of static rows per table
        """

    def generate(self, output_path: str) -> str:
        """
        Generate the .var file.

        Steps:
        1. Write file header with metadata
        2. Write scalar entries (OIDs with index_type="S")
           - Append ".0" to OID for scalar instance
           - Use appropriate value type based on syntax and access
        3. Write table entries:
           - Group columns by table
           - Add %sapdefine for row count
           - Use range notation [1-NUMROWS_<table>] for integer-indexed tables
           - Use indexvalue(0) for index columns
        4. Write dynamic row creation section:
           - Fully detected tables → uncommented %drow/%dcol blocks
           - Undetectable tables → commented out with warning
        5. Return output file path
        """

    def _write_scalar(self, entry: OidEntry) -> str:
        """Format a scalar variable line: <oid>.0 , <type> , <access> , <value_info>"""

    def _write_table(self, table_name: str, columns: list[OidEntry]) -> list[str]:
        """
        Format all lines for a static table definition.
        Includes %sapdefine, index columns with ranges, and data columns.
        """

    def _write_dynamic_rows(self, config: DynamicRowConfig) -> list[str]:
        """
        Format the %drow/%dcol/%setaction block.
        If config.is_fully_detected is False, prefix all lines with '#'.
        """

    def _get_value_info(self, entry: OidEntry, is_index: bool = False) -> str:
        """
        Determine the value info string for a variable.
        Uses the mapping tables above based on syntax and access level.
        """
```

## 9. Main Compiler Orchestrator (`compiler.py`)

### Purpose

The main entry point that coordinates the full pipeline.

```python
class MibCompiler:
    """
    Main orchestrator for the MIB compilation pipeline.

    Pipeline:
    1. Parse MIB ZIP → list of OidEntry
    2. Parse OIDs PDF → list of PdfTableInfo
    3. Cross-reference MIB + PDF → detect dynamic row configs
    4. Generate .cmf from MIB data
    5. Generate .var from MIB data + dynamic row configs
    6. Return CompilationResult
    """

    def __init__(
        self,
        mib_zip_path: str,
        oids_pdf_path: str,
        output_dir: str = "/opt/sapro/cmf",
        var_output_dir: str = "/opt/sapro/var",
        output_name: Optional[str] = None,  # e.g., "DP_10_12" — auto-detected if None
        num_rows: int = 2
    ):
        """
        Args:
            mib_zip_path: Path to uploaded MIB ZIP file
            oids_pdf_path: Path to uploaded OIDs PDF file
            output_dir: Directory for .cmf output
            var_output_dir: Directory for .var output
            output_name: Base name for output files (without extension)
            num_rows: Default number of static rows per table in .var
        """
        self.mib_zip_path = mib_zip_path
        self.oids_pdf_path = oids_pdf_path
        self.output_dir = Path(output_dir)
        self.var_output_dir = Path(var_output_dir)
        self.output_name = output_name
        self.num_rows = num_rows
        self.warnings: list[str] = []

    def compile(self) -> CompilationResult:
        """
        Run the full compilation pipeline.

        Steps:
        1. Create temporary working directory
        2. Parse MIB files:
           mib_parser = MibParser(self.mib_zip_path, work_dir)
           oid_entries = mib_parser.parse()
        3. Parse OIDs PDF:
           pdf_parser = PdfParser(self.oids_pdf_path)
           pdf_tables = pdf_parser.parse()
        4. Detect dynamic rows:
           detector = DynamicRowDetector(oid_entries, pdf_tables)
           dynamic_rows = detector.detect_all()
        5. Auto-detect version and output name if not provided
        6. Generate .cmf:
           cmf_gen = CmfGenerator(oid_entries)
           cmf_path = cmf_gen.generate(self.output_dir / f"{self.output_name}.cmf")
        7. Generate .var:
           var_gen = VarGenerator(oid_entries, dynamic_rows, version, self.num_rows)
           var_path = var_gen.generate(self.var_output_dir / f"{self.output_name}.var")
        8. Collect stats and warnings
        9. Clean up temp directory
        10. Return CompilationResult

        Error handling:
        - MIB parse errors should be collected but not fatal (skip broken MIBs)
        - PDF parse errors should be collected but not fatal (skip dynamic rows)
        - File I/O errors are fatal
        """

    def _auto_detect_version(self, pdf_parser: PdfParser, mib_parser: MibParser) -> str:
        """
        Try to detect version from:
        1. PDF title (e.g., "DefensePro X version 10.12.0.0")
        2. ZIP filename
        3. MIB file paths inside ZIP
        """

    def _generate_output_name(self, version: str) -> str:
        """Convert version to output name: "10.12.0.0" → "DP_10_12" """
```

## 10. API Route (`routes/oid_compiler.py`)

```python
from fastapi import APIRouter, UploadFile, File, Form, HTTPException
from fastapi.responses import JSONResponse
import tempfile
import shutil
from ..modules.sapro.oid_compiler.compiler import MibCompiler
from ..modules.sapro.oid_compiler.models import CompilationResult

router = APIRouter(prefix="/api/oid-compiler", tags=["OID Compiler"])


@router.post("/compile", response_model=CompilationResult)
async def compile_mibs(
    mib_zip: UploadFile = File(..., description="MIB ZIP file from Radware portal"),
    oids_pdf: UploadFile = File(..., description="OIDs PDF document"),
    output_name: str = Form(None, description="Output filename base (auto-detected if empty)"),
    num_rows: int = Form(2, description="Number of static rows per table"),
    cmf_output_dir: str = Form("/opt/sapro/cmf", description="CMF output directory"),
    var_output_dir: str = Form("/opt/sapro/var", description="VAR output directory"),
):
    """
    Compile MIB files and OIDs PDF into SAPRO .cmf and .var files.

    Upload both a MIB ZIP file and an OIDs PDF document for the same
    DefensePro version. The compiler will:
    1. Parse MIB files to extract OID definitions with full metadata
    2. Parse the PDF to extract table structure information
    3. Generate a .cmf file with all OIDs, types, ranges, and enums
    4. Generate a .var file with scalars, static tables, and dynamic
       row creation blocks

    The .var file includes fully functional %drow/%dcol blocks for
    tables that support dynamic row creation (rowstatus, rmonstatus,
    and newinstance types).
    """
    # Save uploaded files to temp directory
    tmp_dir = tempfile.mkdtemp(prefix="mib_compiler_")
    try:
        zip_path = os.path.join(tmp_dir, mib_zip.filename)
        pdf_path = os.path.join(tmp_dir, oids_pdf.filename)

        with open(zip_path, "wb") as f:
            shutil.copyfileobj(mib_zip.file, f)
        with open(pdf_path, "wb") as f:
            shutil.copyfileobj(oids_pdf.file, f)

        # Run compilation
        compiler = MibCompiler(
            mib_zip_path=zip_path,
            oids_pdf_path=pdf_path,
            output_dir=cmf_output_dir,
            var_output_dir=var_output_dir,
            output_name=output_name,
            num_rows=num_rows,
        )
        result = compiler.compile()
        return result

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        shutil.rmtree(tmp_dir, ignore_errors=True)
```

## 14. Implementation Order

Implement in this order to allow incremental testing:

1. **`models.py`** + **`constants.py`** — Data structures and mappings (no logic, just definitions)
2. **`mib_parser.py`** — Parse MIB files. Test with a real DefensePro MIB ZIP. This is the most complex and uncertain component (pysmi integration).
3. **`cmf_generator.py`** — Generate CMF from parsed entries. Test by comparing output to a known-good CMF file.
4. **`pdf_parser.py`** — Parse OIDs PDF. Test with the real DefensePro OIDs PDF.
5. **`dynamic_row_detector.py`** — Cross-reference MIB + PDF data. Test detection patterns against known tables.
6. **`var_generator.py`** — Generate VAR file. Test scalar format, table format, and dynamic row blocks.
7. **`compiler.py`** — Wire everything together. End-to-end test.
8. **`routes/oid_compiler.py`** — API endpoint. Test file upload and response.
9. **Frontend** — UI components. Last because the backend can be tested via curl/Postman.

## 15. Risk Areas and Mitigation

### Risk 1: pysmi Compatibility

**Risk**: pysmi may not handle all Radware proprietary MIB constructs, or may have dependency issues.

**Mitigation**: 
- Test pysmi early with a real DefensePro MIB ZIP (step 2 in implementation order)
- If pysmi fails, fallback to a custom regex-based MIB parser. The MIB files follow SMIv2 syntax, and we only need to extract: OBJECT-TYPE definitions (OID, SYNTAX, ACCESS, STATUS, DESCRIPTION, INDEX), TEXTUAL-CONVENTION definitions (DisplayHint, STATUS, DESCRIPTION, SYNTAX), and OBJECT IDENTIFIER assignments.
- Another fallback: use the `smidump` command-line tool (from libsmi) via subprocess if available on the system.

### Risk 2: PDF Parsing Accuracy

**Risk**: pdfplumber may not accurately extract the OIDs PDF tables due to complex layout.

**Mitigation**:
- Implement the fallback text-mode parser using `pdftotext -layout` (described in section 5)
- The OIDs PDF has a consistent layout — column positions can be determined from the header row
- Test early with the real PDF

### Risk 3: Newinstance Detection False Positives/Negatives

**Risk**: The regex patterns may not catch all cases or may match incorrectly.

**Mitigation**:
- Start conservative: only the three confirmed patterns
- Undetected tables are commented out (never broken syntax)
- Add a stats counter showing "X tables detected, Y tables commented out" so the user knows
- The patterns can be extended over time as more DefensePro versions are analyzed

### Risk 4: MIB-PDF Cross-referencing

**Risk**: OID labels or table names may not match exactly between MIB and PDF sources.

**Mitigation**:
- Use OID numeric path as the primary join key (not label names)
- Fall back to fuzzy label matching if OID matching fails
- Log warnings for unmatched entries
